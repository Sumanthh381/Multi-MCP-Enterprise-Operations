# Validation evidence

Run date: 27 October 2026. Reports here are generated by actual commands, not illustrative passing output.

- Python 3.12: full pytest suite passes; final count and exact coverage are in `tests.xml` and `coverage.json`.
- Coverage includes API, backend and both MCP subprocesses via coverage subprocess instrumentation. It is line coverage, not branch coverage or proof of all behavior.
- `ruff check`, `ruff format --check`, and `mypy src/enterprise` pass.
- All three supplied Postman collections completed: 15 baseline requests, 15 scenario requests and 32 chaining requests. All returned 200 and no script/request failures were reported. The ten chaining flows use top-level `pm.expect`, which Newman does not count as named assertions. JSON reports retain request/response evidence.
- API tests independently assert computation, authentication, pagination, metadata, filtering, invalid requests and safe KPI execution.
- Real MCP tests discover both servers, execute all 17 tools, pass outputs between tools, reject invalid schemas and missing tools, verify trace propagation, and enforce explicit write confirmation/idempotence.
- Backend E2E tests combine real stdio MCP calls, source API, SQLite maintenance and retrieval. Multiple intents, conversation retention, empty windows and partial-source failure pass.
- Browser automation passed actual schema inspection, combined investigation, citations, explicit ticket confirmation, degraded maintenance and mobile rendering; no browser JavaScript errors were observed. Screenshots and MP4 are committed. The video is a silent real browser capture, not a mocked animation.
- Docker Compose built both images, started both services healthy, and passed `scripts/smoke.py` against the containerized workflow. A non-root corpus permission issue discovered by this check was fixed; an unreadable/missing corpus now fails startup.
- This builder cannot resolve package/proxy hosts from build containers. Packages were downloaded on the host with normal TLS verification into the ignored `.build-wheels` directory; the Dockerfile's optional wheel-cache path supplied those same pinned artifacts. Clean online Docker installation is left to CI/normal developer networking; the tested container build used the local cache.
- `pip-audit` on the pinned dependency set reported no known vulnerabilities at run time. This is not a guarantee of security. See `dependency-audit.json`.
- One upstream FastAPI/Starlette HTTPX TestClient deprecation warning is preserved in the test report; it does not fail tests.

Not claimed: remote GitHub Actions completion, evaluator access grants, remote LLM behavior, production authentication, strict red/green TDD history or industrial safety validation. GitHub API publication status is tracked in the submission notes.
